# 연구실 세미나 Discord 봇

요일별 발표자 순환, 아침 발표 알림, 저녁 자료 요청, 순서 교환, 휴강 처리를 지원합니다. 매회 **발표 자료 1개 이상과 서로 다른 논문 PDF 3편 이상**을 제출받습니다. 발표 자료 원본은 보관하고, 새 논문 PDF는 잠시 분석한 뒤 삭제하여 제목·파일명·DOI·arXiv ID·해시·발표 회차만 기록합니다. 논문 본문은 DB에 저장하지 않으며 메타정보로 검색·중복 확인과 제출 현황을 계산합니다. Python 3.12 이상과 SQLite를 사용합니다.

## Discord 봇 준비

1. [Discord Developer Portal](https://discord.com/developers/applications)에서 애플리케이션을 만들고 **Bot** 페이지에서 봇 토큰을 발급합니다.
2. **Bot → Privileged Gateway Intents → Message Content Intent**를 켭니다. 이 봇은 일반 채널 메시지의 첨부파일을 받아야 하므로 이 설정이 필요합니다. [Discord의 Message Content Intent 설명](https://docs.discord.com/developers/events/gateway#message-content-intent)
3. **Installation** 또는 **OAuth2 → URL Generator**에서 서버 설치 링크를 만듭니다. 범위는 `bot`, `applications.commands`를 선택합니다. 봇 권한은 **View Channels, Send Messages, Read Message History, Embed Links**를 허용합니다. 알림 채널과 업로드 채널에서도 이 권한이 있어야 합니다. Administrator 권한은 필요하지 않습니다. [Discord 공식 설치 안내](https://docs.discord.com/developers/quick-start/getting-started#installing-your-app)
4. 링크로 연구실 서버에 봇을 초대합니다. Discord에서 설정·스왑·연기를 사용할 사람에게는 **서버 관리(Manage Server)** 권한이 있어야 합니다. 전체 발표 순서는 NAS 파일 편집 권한이 있는 사람이 JSON으로 관리합니다.

Discord 기능은 Gateway에 연결하므로 공개 웹 서버나 Interactions Endpoint URL을 설정하지 않아도 됩니다. 홈페이지 연동을 사용하는 경우에는 별도의 인증된 API 연결을 설정합니다. 서버 멤버는 명령어를 사용할 채널에서 **Use Application Commands** 권한이 있어야 합니다.

## 로컬 실행

프로젝트 디렉터리에서 실행합니다.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
cp .env.example .env
```

`.env`의 `DISCORD_TOKEN`에 봇 토큰을 입력한 뒤 실행합니다.

```bash
python -m seminar_bot
```

`seminar-bot` 명령으로도 실행할 수 있습니다. 명령어는 시작할 때 등록합니다. 빠르게 테스트하려면 Discord 개발자 모드를 켜서 서버 ID를 복사하고 `DISCORD_GUILD_ID`에 넣으세요. 비워 두면 전역 명령어로 등록되며 Discord에 반영되기까지 시간이 걸릴 수 있습니다. [Discord 명령어 등록 범위](https://docs.discord.com/developers/interactions/application-commands#registering-a-command)

| 환경변수 | 기본값 | 설명 |
| --- | --- | --- |
| `DISCORD_TOKEN` | 필수 | 봇 토큰. 저장소에 커밋하지 마세요. |
| `DISCORD_GUILD_ID` | 빈 값 | 개발용 서버 ID. 비우면 전역 등록 |
| `DATA_DIR` | `./data` | SQLite, 보관할 발표 자료 원본, 실행 잠금 저장 위치 |
| `MAX_FILE_MB` | `20` | 파일 1개당 처리 한도(MiB), 1~100 설정 가능. Discord 업로드 한도는 별도 |
| `LOG_LEVEL` | `INFO` | 로그 수준 |
| `ROTATION_FILE` | `config/rotation.json` | 발표 순서 JSON 경로. Compose에서는 `/app/config/rotation.json`으로 지정 |

## 처음 설정하기

아래 예시는 Discord 입력창에서 각 옵션을 선택해 입력하는 형태입니다. 사용자와 채널은 실제 서버의 항목을 선택하세요.

```text
/설정 weekday:목요일 channel:#세미나 upload_channel:#발표자료 세미나시간:14:00 morning:09:00 evening:18:00 timezone:Asia/Seoul
```

`세미나시간`은 매주 고정된 세미나 시작 시각이며, 아침 알림·저녁 자료 요청·`/일정`에 표시합니다. 알림을 보내는 시각은 `morning`·`evening`으로 따로 지정합니다. `세미나시간`을 생략하면 기존 시작 시각을 유지하고, 처음 설정할 때 생략하면 시작 시각은 미설정 상태로 둡니다.

발표 순서는 `/순서설정` 명령어 대신 NAS 프로젝트 폴더의 **`config/rotation.json`**에서 관리합니다. 처음 한 번 아래 절차로 파일을 만들고, 이후에는 VS Code로 JSON만 수정하면 됩니다. 봇이 파일 저장 후 **30초 안에 변경을 확인**하며 `/일정`을 열 때도 확인합니다. 재시작이나 이미지 재빌드는 필요하지 않습니다.

NAS에서 최신 코드를 받은 뒤 최초 한 번 실행합니다. 기존 봇을 잠시 중지하고 기존 DB의 순서를 JSON으로 내보냅니다. 기존 일정·스왑·휴강·자료는 유지하며 이미 JSON이 있으면 덮어쓰지 않습니다. 설정된 서버가 한 곳이면 서버 ID 없는 형식으로 내보내며, 기존 명단이 없으면 `{"start_date": null, "presenters": []}`로 생성됩니다.

```bash
cd "$HOME/seminar-bot"
sudo docker compose build
sudo docker compose stop seminar-bot
if [ ! -f config/rotation.json ]; then
  sudo docker compose run --rm --no-deps -T seminar-bot python -m seminar_bot.rotation > config/rotation.json.tmp &&
    mv config/rotation.json.tmp config/rotation.json
fi
sudo docker compose up -d
```

로컬 Python 실행 환경에서는 `python -m seminar_bot.rotation > config/rotation.json`으로 내보낼 수 있습니다. 먼저 봇을 중지하고 기존 JSON을 덮어쓰지 않도록 확인하세요. 빈 명단으로 처음 시작할 경우 `cp -n config/rotation.example.json config/rotation.json`으로 만들 수도 있습니다.

JSON의 예시입니다. 서버 ID는 입력하지 않습니다. 아래 사용자 ID는 예시이므로 실제 발표자의 ID로 바꾸세요. Discord **사용자 설정 → 고급 → 개발자 모드**를 켠 뒤 사용자 프로필의 우클릭 메뉴에서 **사용자 ID 복사**로 확인할 수 있습니다.

```json
{
  "start_date": null,
  "presenters": [
    {"user_id": "234567890123456789", "name": "철수"},
    {"user_id": "345678901234567890", "name": "영희"},
    {"user_id": "456789012345678901", "name": "민수"}
  ]
}
```

- `/설정`을 마친 서버가 한 곳이면 그 서버에 자동으로 적용합니다. 기존 `{"guilds": {"서버 ID": {...}}}` 형식도 계속 지원하며, 여러 서버를 설정한 경우에는 서버별 형식을 사용해야 합니다. 대상 서버를 임의로 고르지 않습니다.
- `presenters`의 배열 순서대로 매주 한 명씩 반복합니다. **변경 후 첫 발표자로 삼을 사람을 배열 맨 앞**에 둡니다. `user_id`는 숫자 문자열이어야 하며 중복·봇 계정·해당 서버에 없는 계정은 거절합니다. `name`은 생략 가능한 관리용 이름으로, 멘션과 일정에는 ID를 사용합니다.
- `start_date: null` 또는 항목 생략 시 다음 예정 회차부터 새 배열을 적용합니다. 기존 휴강일은 건너뜁니다. 오늘 발표의 알림을 이미 보냈거나 자료가 연결되어 있으면 다음 회차부터, 오늘 저녁 요청 시간이 지났으면 다음 주부터 적용합니다.
- 적용일을 직접 정하려면 `start_date`를 `"2026-10-22"`처럼 지정합니다. 오늘 이후이며 설정한 세미나 요일이어야 합니다. 전체 순서를 다시 바꾸는 시점에 지난 날짜가 남아 있으면 수정하거나 `null`로 바꾸세요.
- **전체 순서가 바뀌면 적용일 이후 발표 일정과 휴강 설정을 새로 만듭니다.** 변경 범위에 자료나 발송 이력이 있으면 적용을 거절하므로 그 이후 날짜를 지정하세요. 적용일 이전의 일정·자료는 유지합니다.
- 파일의 명단·적용일이 같으면 재적용하지 않습니다. 파일 저장·재시작·이름 수정이나 서버별 형식에서 단일 서버 형식으로의 변환만으로 기존 `/스왑`, `/연기` 결과를 되돌리지 않습니다. 명단을 비우거나 서버별 항목을 파일에서 지우는 것만으로 기존 일정을 삭제하지 않습니다.
- JSON 문법, ID, 적용일 등에 오류가 있으면 해당 변경을 적용하지 않고 기존 일정으로 운영합니다. `sudo docker compose logs --tail=100 seminar-bot`에서 이유를 확인하세요. `/일정`에도 파일 적용 오류 여부를 표시합니다.

실제 `config/rotation.json`과 임시 파일은 Git과 이미지에서 제외합니다. 호스트의 `config` 디렉터리 전체를 컨테이너에 읽기 전용으로 연결하여 VS Code의 파일 교체 저장도 반영합니다. 명단은 DB·자료와 함께 별도로 백업하세요.

등록 후 Discord에서 `/일정 weeks:8`로 확인합니다. 시간대는 `Asia/Seoul` 같은 IANA 이름을 사용하고, 시간은 24시간제 `HH:MM`으로 입력합니다. 아침 알림 시간은 저녁 요청 시간보다 빨라야 합니다.

`/설정`에서 요일을 바꾸면 오늘을 포함한 앞으로의 발표와 휴강일을 새 요일에 맞춰 0~6일 뒤로 이동합니다. 발표 순서와 연결된 자료는 유지합니다.

| 명령어 | 기능 | 권한 |
| --- | --- | --- |
| `/설정` | 요일, 세미나 시작 시각, 채널, 알림 시간, 시간대 지정 | 서버 관리 |
| `/일정 weeks` | 앞으로 1~20주 표시, 기본 8주 | 모든 멤버 |
| `/스왑 first_date second_date` | 두 날짜의 발표자 교환 | 서버 관리 |
| `/연기 from_date` | 해당 회차를 한 주 휴강하고 이후 일정을 모두 7일 이동 | 서버 관리 |
| `/검색 query page kind` | 제목, 파일명, DOI, arXiv ID 검색. 기본은 논문 | 모든 멤버 |
| `/제출현황 seminar_date` | 발표 자료·논문 PDF 개수와 부족한 항목 확인 | 모든 멤버 |
| `/자료수정 record_id title` | 자동 추출된 자료 제목 수정 | 업로더 또는 서버 관리 |
| `/자료연결 record_id seminar_date` | 자료를 발표 날짜에 연결 | 업로더 또는 서버 관리 |
| `/자료분류 record_id kind` | 발표 자료·논문 PDF·분류 미확정으로 수정 | 업로더 또는 서버 관리 |
| `/도움말` | 사용법 표시 | 모든 멤버 |

날짜는 `YYYY-MM-DD` 형식입니다. 스왑은 선택한 두 회차에만 적용되고 JSON의 반복 명단 자체는 유지합니다. 미리 올려 연결한 자료도 발표자를 따라 교환된 날짜로 이동합니다.

```text
/스왑 first_date:2026-10-22 second_date:2026-10-29
/연기 from_date:2026-10-22
```

예를 들어 10월 22일 A, 10월 29일 B, 11월 5일 C 순서였다면, 10월 22일부터 연기하면 10월 22일은 휴강하고 10월 29일 A, 11월 5일 B, 11월 12일 C가 됩니다. 이후에 생성되는 일정도 같은 순서로 이어집니다. `/연기`의 날짜를 생략하면 다음 예정 회차를 연기합니다.

## 파일 업로드와 제출 현황

매회 **발표 자료 1개 이상(PDF/PPT/PPTX)과 서로 다른 논문 PDF 3편 이상**을 제출합니다. 봇이 켜져 있을 때 설정한 업로드 채널에 파일을 첨부하면 자동으로 등록합니다. 한 메시지에 모아서 올리거나 여러 메시지로 나눠 올려도 같은 발표 회차의 기록은 누적됩니다. `/논문 등록` 같은 수동 등록은 필요하지 않습니다. 봇이 꺼져 있는 동안 올린 파일이나 기존 채널 기록은 자동으로 수집하지 않으므로 파일을 다시 올려주세요.

홈페이지 연동을 켰다면 `/internal/seminars/`에서 회차를 선택하고 두 영역에 파일을 추가한 뒤 **선택한 자료 등록 → 제출 완료하기**로 진행할 수도 있습니다. 구분과 회차를 직접 선택하므로 Discord의 PDF 분류 버튼이나 자동 회차 추정을 거치지 않습니다. 파일별 기본 한도는 20 MiB이며 웹에서는 최대 20 MiB까지 받습니다. 성공한 발표 자료 원본과 논문 메타정보는 다른 항목의 실패와 관계없이 남고, 같은 업로드의 재시도는 중복 등록하지 않습니다. 일정이 변경되면 처리를 중단하고 변경된 날짜·발표자를 다시 확인하도록 요청합니다. Discord 알림만 실패한 경우에는 자료를 다시 올리지 않고 **Discord 알림 다시 보내기**를 사용할 수 있습니다.

- PPT/PPTX는 발표 자료로 분류합니다. PDF는 파일명, DOI/arXiv ID 등의 단서로 발표 자료 또는 논문 PDF를 추정합니다.
- PDF의 구분이 애매하면 **발표 자료 / 논문 PDF** 버튼을 보여줍니다. 업로더 또는 서버 관리자가 선택하면 분류가 저장됩니다. 봇 재시작 후에도 버튼을 사용할 수 있습니다. 분류 미확정 파일은 제출 수량에 포함하지 않습니다. **새 논문 PDF와 미확정 PDF는 원본을 보관하지 않습니다.** 나중에 발표 자료로 분류해도 삭제한 원본이 복원되지는 않으므로 원본이 필요하면 발표 자료임을 표시해 다시 올립니다.
- Discord에서 발표 자료 PDF를 올릴 때는 업로드 메시지에 **발표자료** 또는 **발표 자료**를 표시하거나 발표 자료임이 명확한 파일명을 사용합니다. 홈페이지에서는 **발표 자료** 영역을 사용합니다. PPT/PPTX와 명확하게 지정된 발표 자료 PDF는 원본을 보관합니다.
- PDF는 메타데이터와 처음 3페이지, PPTX는 처음 5슬라이드의 텍스트를 분석에 사용합니다. 논문과 미확정 PDF는 분석 후 본문을 DB에 남기지 않습니다. 예전 형식인 `.ppt`는 내부 텍스트를 분석하지 않고 원본과 파일명만 보관합니다.
- 논문에는 원본 파일명, 추출 제목, SHA-256, DOI/arXiv ID, 발표 회차와 업로드·출처 정보를 기록합니다. 파일의 SHA-256, DOI/arXiv ID, 제목을 비교해 이전 자료 후보도 안내합니다. 새 논문 PDF는 임시 처리 후 삭제하며 NAS 자료 볼륨에 원본을 쓰지 않습니다.
- 업로더가 발표자인 가까운 회차가 업로드 시점 기준 7일 이내에 있으면 자동으로 연결합니다. 찾지 못하면 미연결 자료로 보관하므로 `/자료연결`로 발표 날짜를 지정하세요.
- 같은 파일이나 같은 논문의 중복 업로드는 논문 3편을 채우는 데 중복 계산하지 않습니다. 파일 해시, DOI, arXiv ID, PDF 메타데이터의 유효한 제목으로 중복을 확인합니다. 동일한 파일을 발표 자료와 논문 PDF 양쪽에 동시에 계산하지 않습니다.
- 자료 ID로 제목·분류·발표 날짜를 고칠 수 있습니다. 일반 업로더는 자신이 올린 자료를 자신의 발표 회차에 연결할 수 있고 서버 관리자는 다른 발표자의 자료도 정리할 수 있습니다.

```text
/제출현황
/제출현황 seminar_date:2026-10-22
/자료분류 record_id:12 kind:논문 PDF
/자료수정 record_id:12 title:Attention Is All You Need
/자료연결 record_id:12 seminar_date:2026-10-22
```

`/제출현황`은 발표 자료와 서로 다른 논문 PDF의 현재 개수, 분류 미확정 파일, 부족한 항목을 보여줍니다. 날짜를 생략하면 오늘의 발표가 있으면 오늘, 없으면 최근 7일 이내의 지난 발표, 그것도 없으면 다음 발표를 선택합니다. 미연결 자료는 회차 제출 현황에 포함되지 않습니다. `/자료분류`의 `kind`는 **발표 자료 / 논문 PDF / 분류 미확정** 중에서 선택합니다. PPT/PPTX를 논문 PDF로 분류할 수는 없습니다.

검색과 제출 현황은 요청한 사람에게만 표시합니다. 원본 업로드 채널의 채널 보기·메시지 기록 보기 권한이 있는 자료만 보여주고 계산하므로 사용자의 접근 권한에 따라 현황이 다를 수 있습니다. 중복 업로드 안내도 같은 자료 채널의 기존 기록만 참조합니다.

## 검색과 보관

`/검색`은 기본적으로 **논문**만 검색합니다. `kind` 옵션에서 **논문 / 발표 자료 / 분류 미확정 / 전체**를 선택할 수 있습니다.

```text
/검색 query:attention
/검색 query:10.1234/example page:1
/검색 query:세미나 kind:발표 자료
/검색 query:attention kind:전체
```

이미지로 스캔한 PDF의 OCR, 외부 논문 사이트 조회, LLM 추출은 사용하지 않습니다. 슬라이드의 제목이 실제 논문 제목과 다를 수 있으므로 필요하면 `/자료수정`으로 고쳐주세요. 검색 결과는 저장된 자료와 연결된 발표 날짜를 보여줍니다. 미래 발표에 올린 자료도 검색될 수 있습니다.

`MAX_FILE_MB`는 파일 처리 한도입니다. 문서 분석에는 별도로 25 MiB 한도가 있어서, 처리 한도를 늘리더라도 이를 넘는 파일은 파일명 중심으로 기록합니다. 발표 자료일 때만 원본을 보관하며 논문·미확정 PDF의 원본 미보관 정책은 크기와 관계없이 유지합니다. 손상·암호화되었거나 분석 용량·시간 한도를 넘은 문서도 파일명으로 기록할 수 있습니다.

발표 자료 원본은 `DATA_DIR`에 남으므로 Discord 첨부 URL의 만료에 의존하지 않습니다. 새 논문 PDF는 **원본 미보관**으로 표시하고 NAS 다운로드를 제공하지 않으며, 유효한 DOI/arXiv가 있으면 외부 논문 페이지로 이동할 수 있습니다. Discord로 올린 자료의 검색 링크는 원본 메시지이며, 메시지가 삭제되거나 채널 접근 권한이 사라지면 그 링크는 열리지 않을 수 있습니다. **Discord에 직접 첨부한 PDF는 Discord 메시지에 남으며 봇이 그 메시지를 자동 삭제하지 않습니다.** 웹으로 올린 자료의 링크는 현재 발표 회차의 홈페이지 제출 화면입니다. 웹 연동 시에는 로그인한 홈페이지에서 보관된 발표 자료를 다운로드할 수 있습니다.

새 논문의 원본·본문 미보관 정책은 이 버전 이후의 새 제출부터 적용합니다. 이전 버전이 이미 저장한 PDF·본문은 업데이트 과정에서 자동 삭제하지 않습니다. 기존 원본이 있는 기록은 계속 다운로드할 수 있으며 과거 원본을 정리하려면 별도 검토 후 명시적으로 삭제해야 합니다. 임시 파일 삭제를 저장장치의 복구 불가능한 삭제로 보장하지는 않습니다.

현재 추출기는 가벼운 `pypdf`로 PDF 메타데이터와 제한된 페이지를 확인하며, 메타데이터가 비어 있으면 파일명 등을 사용합니다. [pypdf 메타데이터 안내](https://pypdf.readthedocs.io/en/stable/user/metadata.html) 향후 자체 호스팅한 [GROBID의 `processHeaderDocument`](https://grobid.readthedocs.io/en/latest/Grobid-service/#apiprocessheaderdocument)로 서지 추출을 보강할 수 있지만 기본 구성에는 추가하지 않았습니다. [Crossref의 DOI 메타데이터 조회](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) 역시 향후 선택 기능이며 현재 구현에는 없습니다. 기본 동작은 PDF를 외부 서지 서비스에 전송하지 않습니다.

## 알림 동작과 운영

설정한 시간대의 발표 당일 아침에 발표자를 멘션하고, 저녁에 같은 발표자에게 **발표 자료와 논문 PDF 3편**을 공유해 달라고 요청하면서 현재 제출 현황을 알려줍니다. `SEMINAR_PAGE_URL`을 설정하면 해당 회차의 홈페이지 제출 링크도 함께 보냅니다. 웹 제출 완료 시에는 자료 채널에 완료 알림을 남깁니다. 부족한 파일이 있어도 추가로 재촉하는 알림을 반복 발송하지 않습니다. 30초 간격으로 발송 여부를 확인합니다. SQLite에 발송 이력을 기록하므로 정상 재시작으로 같은 알림이 반복되지 않습니다. 당일 늦게 켜지면 아직 유효한 알림을 보충하되 저녁 시간이 지난 아침 알림과 지난 날짜의 알림은 보내지 않습니다. 당일 발표자를 스왑하면 변경된 발표자에게 해당 시간대의 알림을 다시 보냅니다.

Discord 전송 직후 이력을 저장하기 전에 프로세스가 강제로 종료되면 드물게 중복될 수 있습니다. 동일한 데이터 디렉터리를 사용하는 프로세스는 운영체제 파일 잠금으로 한 개만 실행합니다. 여러 복제본이나 별도 데이터 디렉터리로 같은 토큰을 동시에 실행하지 마세요. 예약 시각에 알림을 보내려면 호스트와 봇이 실행 중이어야 합니다.

기존 데이터베이스는 시작할 때 v7로 자동 갱신합니다. 일정·자료·발송 이력과 제출 권한을 유지하면서 세미나 시작 시각을 저장할 항목을 추가합니다. 기존 설정의 시작 시각은 미설정 상태이며 `/설정`에서 지정할 수 있습니다. 이전 자료의 분류 정보가 없으면 파일 정보를 바탕으로 분류를 추정합니다. 기존 PDF가 잘못 분류되거나 분류 미확정이면 `/자료분류`로 정리할 수 있습니다.

## 검증

Discord 연결 없이 일정 계산, 연기·스왑, 파일 정보 추출, 분류, 중복 논문 집계, 제출 현황, 검색 등 핵심 로직을 검증합니다.

```bash
python -m unittest discover -s tests -v
ruff check .
```

실제 Discord 로그인, 명령어 표시, 채널 권한과 예약 메시지 수신은 봇 토큰을 넣은 테스트 서버에서 확인해야 합니다. 토큰 없이 실제 서버 연결까지 검증한 것으로 간주하지 않습니다.
